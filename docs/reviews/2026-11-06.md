## Relevant upstream Drizzle review

Checked public npm metadata and the published source artifacts, not unrelated
upstream features or an unverified moving branch:

| Package/track | Observed version |
| --- | --- |
| ORM pinned / registry `latest` | 0.45.4 / 0.45.4 |
| Kit previously documented / registry `latest` | 0.31.10 / 0.31.11 |
| ORM and Kit `rc` | 1.0.0-rc.5 |
| ORM and Kit `beta` | 1.0.0-beta.22; neither package has a `next` tag |

- Stable ORM `migrator.js` and `pg-core/dialect.js` are byte-identical between
  0.45.2 and 0.45.4. Journal remains `meta/_journal.json`; `when` supplies
  `folderMillis`/`created_at`. Hashes remain SHA-256 of the complete SQL text,
  including final newlines and breakpoint markers. Execution splits on literal
  `--> statement-breakpoint` and passes the raw chunks to SQL execution.
- PostgreSQL defaults remain `drizzle.__drizzle_migrations` with `id`, `hash`,
  `created_at`. `created_at` is the migration timestamp, not apply time. Stable
  selects greatest `created_at` and applies only strictly newer local entries;
  hashes do not govern application. Statements and tracking inserts run in one
  batch transaction. No stable semantic change requires a new release here.
- Kit 0.31.10 to 0.31.11 adds a warning when journal timestamps are not strictly
  increasing, explicitly describing the skip hazard. This does not eliminate
  drizzle-doctor's high-watermark finding or justify downgrading its severity.
- RC.5 still rejects legacy journal folders and directs users to `drizzle-kit
  up`. It reads `<folder>/migration.sql`, derives timestamps from the first 14
  folder-name characters, and retains whole-file hashing/raw breakpoint
  splitting. PostgreSQL adds `name` and `applied_at` (default-now execution
  metadata; upgraded historical rows may be NULL).
  The async migrator selects pending migrations by recorded **name**, not the
  stable timestamp high-watermark. The upgrade path backfills names using
  timestamps/hashes and errors on unmatched DB migrations. Pending SQL and
  tracking inserts execute transactionally. **Keep v1 unsupported/separate.**
